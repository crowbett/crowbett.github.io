# Plan

Goal: a fast, robust personal site that shows visitors what each project does by running the project's real code in their browser, not a list of GitHub links.

Status (2026-10-25): live at https://crowbett.github.io. Scaffold done. 8 project pages, the demo pipeline proven end to end by the `smoke` demo, gate + headless e2e green. Project demos live: ratelimitd (D1), edgecache (D2), jobrun (D3), kvlite (D4), strata (D6, the first Rust one), codegraph (D7), keel (D8). quorum (Q0, D5) waits on U4: the repo is archived. `docs/tasks.md` is the queue.

## Architecture
- **Generator.** `cmd/site` (Go, goldmark only) renders `content/projects/*.md` through `templates/` into `dist/`, copies `web/` as-is, writes `404.html`, `sitemap.xml`, `robots.txt`. `internal/site/check.go` then fails the build on broken internal links, missing page metadata or a blown budget.
- **Demos.** A project page with `demo: live` gets a "Run the live demo" button. On click, `web/assets/demo.js` starts a Web Worker (`demo-worker.js`) that loads `/wasm/<slug>.wasm` with Go's `wasm_exec.js`, and imports `/demos/<slug>/ui.js`, which renders controls and calls the binary over a JSON RPC. The button states the size. The home stage's raytracer build (110 KB) starts after `load` while the stage is on screen, unless reduced motion, Save-Data, a 2g/3g connection or fewer than 4 cores say not to (decision, 2026-11-09, Stage). Project heads follow the same rules (decision, 2026-11-09, V19): the frame sits in the head and its build starts after `load` once a quarter of the frame is on screen. Gzip sizes from the lock, as the frames state them: ~90 KB (netcode) to ~2,192 KB (grepall); 9 of the 14 project builds are ~1,218 KB or more. Under those rules, and on pages without a project head, nothing downloads until the visitor asks. Contract: `docs/demo-contract.md`.
- **Bridges live in the project repos** (`cmd/webdemo`), so each project's own gate tests them and the demo can never drift from the code it claims to show.
- **Binaries are built locally and committed.** `cmd/wasm build` exports each pinned commit with `git archive` (committed files only, plus pinned sibling repos for `go.mod` replaces) and builds it with `-trimpath -buildvcs=false -ldflags=-s -w`. `demos.lock.json` records commit, sha256, sizes and the Go version; `wasm_exec.js` is copied from that same toolchain. CI runs `wasm check` and never needs access to private repos.
- **Deploy.** `.github/workflows/pages.yml` (push to main): `gate` (then `upload-pages-artifact`) and four `e2e` runners (three split the page tabs with `E2E_SHARD=i/3`, the fourth runs every other test, so the slow-link check never shares 4 vCPUs with demo tabs) run at once; `deploy` waits for all five. Under 60 s. One job ran gate and e2e until 2026-11-08, when 15 projects took it to 55 s of checks (measured) plus ~10 s of upload and deploy (projected). `ci.yml` runs the same gate and e2e jobs on pull requests, and every 3 days on main so main's Go caches never age out: the first push after the split found none and took 105 s (measured, gate 88 s cold vs 19 s warm). Warm, push to live took 53 s (measured 2026-11-09, run of 9a84b58: gate 22 s, slowest e2e shard 35 s, deploy 10 s). Actions SHAs are pinned.

## Decisions
- Public repo on GitHub Pages: free Actions minutes and hosting for public repos, no server to run. Custom domain is a later user decision.
- Go static generator instead of a JS framework: zero npm, one toolchain, the site is itself a small Go project.
- Workers, not the main thread: a demo that loops or panics cannot freeze the page; a call that times out terminates the worker.
- Strict CSP via meta tag (`script-src 'self' 'wasm-unsafe-eval'`): no inline scripts, no third-party anything. Pages cannot set response headers, so the meta tag is the only CSP available.
- Private projects (quorum, keel, strata) ship compiled binaries only. A Go binary keeps function and package names in its symbol table even with `-s -w`; that is accepted, the source is not published.
- Binaries are committed to git. Each rebuild adds ~1-2 MB gzipped to history; GitHub's soft limit is 1 GB for a Pages site and a repo. Revisit (e.g. release assets) if the repo passes ~300 MB.
- The multi-user showcase platform idea is parked: research (2026-10-24, `docs/research.md`) found no proven paid demand. The demo bundle (`web/demos/<slug>/` + binary + lock entry) is kept self-contained so it could become that platform's unit if demand appears.

## Budgets (enforced by `site check`)
| What | Limit |
|---|---|
| One HTML page | 60 KiB |
| CSS one page loads (the stylesheets it links + its demo's `ui.css`) | 48 KiB |
| One demo's `ui.js` | 60 KiB |
| One `.wasm`, gzip -9 | 2.25 MiB |
| All `.woff2` fonts | 32 KiB |
| One share image, `og/*.png` | 100 KiB |
| One reel clip or its poster, `reel/*.mp4` / `*.webp` | 300 KiB |

Measured (lock entries, go1.27.3): the `smoke` binary (encoding/json + runtime) is 4,396,800 bytes, 1,220,218 gzipped. The first real bridge, ratelimitd (three algorithms, `encoding/json`, `math/rand/v2`), is 4,467,874 bytes, 1,246,216 gzipped. edgecache (engine + memstore + `net/http`) is 7,856,488 bytes, 2,181,042 gzipped. jobrun (cronx + job.Policy + embedded `time/tzdata`) is 5,290,873 bytes, 1,474,581 gzipped. The Rust `smoke-rs` binary (serde_json, rustc 1.98.1, R0) is 79,972 bytes, 31,939 gzipped. Bridges that import `net/http` or more will be larger (projected), so keep them lean; TinyGo is an option only if a demo cannot fit.

WASM budget raised from 2 MiB to 2.25 MiB (decision, 2026-10-24, D2): edgecache's engine is an `http.Handler`, so its bridge cannot avoid `net/http`, which links crypto/tls init code (traced with `-ldflags=-dumpdep`). The bridge driving the real engine and memstore was 7,845,205 bytes, 2,176,744 gzipped (lock entry, go1.27.0), 79,592 over 2 MiB. Rejected: disabling inlining (`-gcflags=all=-l`) fit an earlier build at 2,063,987 gzipped (measured) but grew the raw module to 8,495,326 bytes, which the browser must compile; TinyGo lacks the `net/http` server types the engine uses; a bridge over bare `internal/rfc9111` would have to reimplement the engine's unexported orchestration. 2.25 MiB leaves ~178 KB over edgecache (go1.27.3) for later bridges; the next raise is another recorded decision.

CSS budget counts one page, not the site (decision, 2026-10-25, F4): the limit summed every stylesheet, so each new demo's `ui.css` (2,090–3,336 bytes, measured) ate into it although a visitor only ever loads `site.css` and one demo's `ui.css`. After the shared field and label rules moved into site.css the sum was 40,530 bytes with 430 to spare, short of D7 and D8. The limit stays 40 KiB, now on the heaviest page: `site.css` 27,664 bytes plus edgecache's 3,126 is 30,790 (measured at the change), so ~10 KB is free for any one demo. A page's CSS weight, the thing the budget protects, is unchanged.

CSS budget raised from 40 KiB to 48 KiB (decision, 2026-11-08, V14): the command palette, the project title and diagram morph, demo full screen, the Search key and the grouped index with its search box are site-wide, so their rules belong in site.css. That took site.css from 33,302 to ~37,500 bytes (measured), and with grepall's 7,167-byte `ui.css` the heaviest page passed 40 KiB. 8,697 bytes gzipped (measured), which is what crosses the wire. Rejected: a lazily linked palette stylesheet, since the build sums every non-demo stylesheet anyway and a first-open fetch would flash an unstyled dialog. 48 KiB leaves ~3.5 KB on the heaviest page; the next raise is another recorded decision.

CSS budget measures each page (decision, 2026-11-09, V18): the check summed every non-demo stylesheet whether a page loaded it or not, so home-only stage and index rules counted against project pages and the reverse. site.css (41,854 bytes) is now split into site.css (every page: tokens, frame, the shared layers, diagrams, palette; 21,604 bytes), home.css (8,256) and project.css (project page and demo frame; 12,588), and the build sums the stylesheets each HTML page links plus the `ui.css` beside its `data-ui` module. Heaviest page: a project page with grepall's 6,842-byte `ui.css`, 41,034 bytes; home 29,860 (all measured at the change). The budget stays 48 KiB. Rejected: raising it, since what a visitor downloads per page is what the budget protects and that fell.

Share image budget (added 2026-10-24, V7): 1200×630 cards rendered by `cmd/og`, 48,139–66,604 bytes each (measured 2026-10-26), so 100 KiB holds them. The build also fails when a card's HTML, site.css or a font no longer matches the hash recorded when its PNG was made (`web/og/.sums`, `site.ImageSum`): run `go run ./cmd/og` and commit `web/og`. Diagram masks work the same way: `go run ./cmd/dither` (needs Chrome and oxipng) writes `web/assets/dg/*.png` and `.sums`.

Reel clip budget (added 2026-11-09, Reel): the home reel plays a 16:10 clip of each live demo, recorded by `go run ./cmd/reel [slug…]` (needs Chrome and ffmpeg) from a dist built with `Config.Recording`, H.264 at 30 fps, in two crops of the demo mount: `<slug>.mp4` from a 752 px wide CSS page at 2x (1408 × 880 px) and `<slug>-n.mp4` from a 480 px page at 3x (1324 × 828 px). A screen about 560 CSS px wide or wider (`site.ReelWide`: 38–63.99rem and 68rem up; the home screen measured 357 px wide at a 390 px viewport, 772 at 820, 612 at 1180 and 705 at 1440) gets the desktop crop at about 1:1, the demo as it runs on the page; a narrower one gets the phone crop, so neither is scaled up far. A `<picture>` picks the poster and the scripts pick the clip from the same media query; pager thumbnails use the phone crop. Each crop is framed on its own (`Focus`/`Pad` for the phone, `WideFocus`/`WidePad` for desktop). The recorder hides the site header and other pinned chrome, stops scroll-linked animations, lets entrances finish, and takes the crop scale from each frame's own width. CRF starts at 26 and steps up by 2 only for a clip that would pass 90% of the budget. Re-recorded 2026-11-09 (V22): the 15 desktop clips measured 44,407–259,379 bytes (anchorflow smallest, raytracer largest), the 15 phone clips 35,191–242,058 bytes (anchorflow, raytracer) and the 30 posters 7,656–72,268 bytes, so 300 KiB holds them; a screen fetches one crop, only the clip in view plays and clips load a viewport ahead, so a visitor never fetches all of them up front. The build fails when a live demo has no clip or its lock entry, `ui.js`, `ui.css` or showcase changed since recording (`web/reel/.sums`): re-record that slug and commit `web/reel`. The home stage poster `reel/stage.webp` (the raytracer at 64 spp, `go run ./cmd/stage`, tied to the lock entry and `site.HomeStage` by `web/reel/.stage`) is 69,416 bytes (measured) under the same limit.

Fonts budget (added 2026-10-24, V2): 32 KiB of woff2. Since V12 (2026-10-26) `make fonts` (`scripts/fonts.sh`) builds four OFL subsets from google/fonts at a pinned commit, sha256-checked: Archivo Expanded 800 (7,752 B), Archivo 400 (7,704 B), Martian Mono 400-700 (9,076 B) and Doto 700 (2,376 B), 26,908 bytes in total (measured), 5,860 under the limit. Rationale in `docs/design.md` §Type.

V12 decisions (2026-10-26, owner-approved): no animation library (CSS `linear()` springs; the libraries that inject `<style>` break the CSP); diagrams are 1-bit masks dithered with an 8×8 Bayer matrix (ordered, so the two motion poses do not crawl; blue noise skipped as a third tool for 112 px drawings); Archivo 400 kept for prose. Details in `docs/design.md` (2026-10-26 V12).
